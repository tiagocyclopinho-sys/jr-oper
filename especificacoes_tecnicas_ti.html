1. Resumo Executivo para a Equipe de T.I. Visão Geral

O JR Oper é uma plataforma corporativa desenvolvida para a centralização e auditoria de processos logísticos críticos (SAC de Devoluções, Investigação de Causa Raiz, Conferência no CD, Ocorrências de Frota em Rota e Gestão de Reentregas).

Definição Arquitetural: O sistema é uma Single Page Application (SPA) e Progressive Web App (PWA) construída no modelo Jamstack / Client-Side First. Foi concebido para ter **zero tempo de compilação**, altíssima performance, execução offline imediata e total desacoplamento entre a camada de apresentação e a camada de persistência em banco relacional.

2. Matriz da Stack Tecnológica Linguagens & Frameworks

Camada Tecnologia / Padrão Detalhamento Técnico
Linguagem Principal JavaScript (ES6+ Vanilla) Utiliza JavaScript moderno sem dependência de transpiladores pesados. Lógica modular desacoplada entre controladores de interface (app.js), estado e persistência (store.js) e conectores de nuvem (cloudStore.js).
Estrutura & Interface HTML5 Semântico + DOM API Renderização dinâmica baseada em componentes reativos nativos, controle de eventos delegados e isolamento de viewport para telas industriais e mobile.
Estilização & Design Tailwind CSS + CSS3 Vanilla Design System corporativo completo com suporte nativo a Dark Mode, responsividade Mobile-First e tipografia otimizada (Plus Jakarta Sans).
Arquitetura PWA Service Workers + Manifest Registro via sw.js com estratégias de cache para execução offline e empacotamento instalável em estações Windows (Edge/Chrome) e celulares Android/iOS.
Manipulação de Dados SheetJS (xlsx.full.min.js) Motor de ingestão e geração de planilhas Excel (.xlsx / .csv) executado diretamente na thread do navegador, sem onerar o servidor.
Persistência Local Web Storage API (LocalStorage) Camada de armazenamento no cliente com índices relacionais, controle transacional, rotinas de integridade de schema e backup de emergência em .JSON.
Banco de Dados (Nuvem) PostgreSQL / Supabase (3FN) Modelagem relacional completa na Terceira Forma Normal contida em database/schema.sql, com chaves estrangeiras, constraints e triggers.
Analytics & BI SQL Views para Power BI Views de alta performance prontas para ingestão via DirectQuery ou Import no Power BI Desktop / Service.

6. Perguntas Frequentes da Equipe de T.I. (FAQ) Q&A

❓ Precisa de servidor Node.js ou compilação (npm run build) para rodar?
Não. O código roda de forma nativa e pura no navegador dos usuários. Isso elimina riscos de quebras de dependências (npm drift) e simplifica o deploy para apenas transferir os arquivos para qualquer servidor web.
❓ Como é feita a persistência de múltiplos usuários simultâneos?
O sistema possui o módulo js/cloudStore.js já configurado para sincronizar em tempo real com instâncias PostgreSQL via Supabase através de API REST / WebSockets, bastando preencher a URL e a chave no arquivo js/config.js.
❓ Como conectar o Power BI da empresa aos dados do sistema?
Basta apontar o conector nativo do Power BI Desktop para a instância PostgreSQL informando as credenciais do banco e selecionar as views prefixadas como vw_bi_*.
